# Existing-key upgrade fixtures

Run `make test-probabilistic-upgrade`. No RedisBloom module is needed.
The checked-in fixtures were generated by RedisBloom v8.11.81 on aarch64
little-endian with a 64-bit pointer ABI. They contain all five families,
populated/empty keys, two databases and absolute expirations in 2100.

`upgrade.py --generate` prints replacement fixture JSON when
`BLOOM_ORACLE_SERVER` and `BLOOM_ORACLE_MODULE` identify the source server.
Review provenance and expected queries before replacing the checked-in data.
Fixtures cover RDB, plain rewritten AOF and RDB-preamble AOF. Do not regenerate
them with the native server: that would stop testing the upgrade boundary.
